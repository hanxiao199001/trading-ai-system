# 资金费率套利策略

## 📊 策略原理

### 什么是资金费率？

资金费率（Funding Rate）是永续合约特有的机制，用于让合约价格锚定现货价格：

- **正资金费率**：多头支付空头（合约价格高于现货）
- **负资金费率**：空头支付多头（合约价格低于现货）
- **结算周期**：通常每8小时结算一次

### 套利逻辑

当资金费率异常高或低时，可以通过持有相应方向的仓位，收取资金费用获利：

```
正资金费率 > 0.1%:
  做空永续合约 → 收取多头支付的资金费

负资金费率 < -0.1%:
  做多永续合约 → 收取空头支付的资金费
```

## ✅ 策略优势

1. **收益明确**：资金费率每8小时结算一次，收益可预期
2. **低风险**：不依赖方向预测，只要持有到结算就能获利
3. **市场中性**：可通过对冲消除方向性风险（进阶版）
4. **高频机会**：每天3次结算，机会较多

## ⚙️ 策略配置

编辑 `config/settings.yaml`：

```yaml
strategy:
  name: "funding_rate_v2"

  # 入场条件
  entry:
    min_funding_rate: 0.0001    # 最小资金费率（0.01%）
    trend_confirm: true          # 是否需要趋势确认
    volume_confirm: true         # 是否需要成交量确认

  # 出场条件
  exit:
    stop_loss: 0.015            # 止损：1.5%
    take_profit: 0.025          # 止盈：2.5%
    max_holding_hours: 24       # 最大持仓时间

  # 风险控制
  risk:
    max_position: 0.3           # 最大仓位比例
    max_daily_loss: 0.02        # 单日最大亏损：2%
    leverage: 3                 # 杠杆倍数
```

## ⚠️ 风险与注意事项

### 风险1：市场剧烈波动

**场景**：持仓期间价格剧烈波动，止损被触发

**应对**：
- 设置合理止损（1.5-2%）
- 控制杠杆（建议≤3x）
- 避开重大事件（美联储会议、重大新闻）

### 风险2：资金费率反转

**场景**：开仓后资金费率快速反转，不但没收到费用，反而要支付

**应对**：
- 监控资金费率变化趋势
- 设置最大持仓时间（24小时）
- 如果费率反转且趋势不利，及时止损

### 风险3：滑点和手续费

**场景**：高频交易导致手续费侵蚀利润

**应对**：
- 只在资金费率>0.1%时开仓（覆盖手续费成本）
- 使用Maker订单降低手续费
- 申请VIP等级获得费率优惠

### 风险4：API故障

**场景**：关键时刻API断连，无法及时止损

**应对**：
- 设置服务器端止损（交易所条件单）
- 部署服务器监控和自动重启
- 保持人工监控（至少每4小时检查一次）

## 📊 改进方向

### 当前问题

1. **盈亏比偏低**（0.42）：平均盈利小于平均亏损
2. **胜率一般**（52.1%）：略高于50%，优势不明显
3. **夏普比率偏低**（1.12）：风险调整后收益不理想

### 改进方案

#### 方案1：现货对冲（推荐）

在持有永续合约的同时，反向持有现货，形成完全对冲：

```
做空永续合约 + 做多现货 = 只赚资金费率，不受价格波动影响
```

**优势**：
- 消除方向性风险
- 最大回撤降至<1%
- 夏普比率提升至>2.0

**劣势**：
- 需要2倍资金
- 现货有持仓成本

#### 方案2：趋势过滤增强

增加更严格的趋势确认条件：

- 多周期趋势一致性（1H + 4H）
- RSI超买超卖区域确认
- 布林带位置判断

#### 方案3：动态止盈止损

根据市场波动率动态调整止盈止损：

```python
if volatility < 0.02:
    stop_loss = 0.01   # 低波动时紧止损
elif volatility > 0.04:
    stop_loss = 0.03   # 高波动时宽止损
```

## 📝 常见问题

### Q1：为什么实盘收益低于回测？

**A**：实盘存在以下额外成本：
- 滑点（0.05-0.1%）
- 手续费侵蚀
- 网络延迟导致入场价差
- 资金费率变化

建议：回测收益打7折作为实盘预期

### Q2：多大资金适合跑这个策略？

**A**：建议配置：
- 最小：1000 USDT（测试用）
- 合适：5000-10000 USDT
- 最大：不超过总资金的30%

### Q3：需要24小时盯盘吗？

**A**：不需要，但建议：
- 每4-8小时检查一次
- 设置止损和最大持仓时间
- 使用监控告警（Telegram Bot）

### Q4：能用在其他币种吗？

**A**：可以，但建议：
- 优先选择主流币（BTC, ETH）
- 流动性好的币种
- 避开小币种（滑点大，风险高）
