# Learning Framework - 学习方法论

个人学习和知识管理框架。

## 核心原则

### 1. 费曼学习法
> 如果你不能简单地解释一件事，说明你还没真正理解它。

```
学习 → 教授 → 发现漏洞 → 重新学习 → 简化表达
```

### 2. 间隔重复
```
第1次复习: 1天后
第2次复习: 3天后
第3次复习: 7天后
第4次复习: 14天后
第5次复习: 30天后
```

### 3. 主动回忆 > 被动阅读
- ❌ 反复阅读笔记
- ✅ 合上书本，尝试回忆

## 技术学习路径

### 新技术评估框架

```yaml
1. WHY (为什么存在):
   - 解决什么问题?
   - 之前的方案有什么不足?

2. WHAT (是什么):
   - 核心概念
   - 关键术语

3. HOW (怎么用):
   - 最小可运行示例
   - 常见使用场景

4. WHEN (何时用):
   - 适用场景
   - 不适用场景
   - 与替代方案对比
```

### 代码学习顺序

```
1. 运行起来 (能跑就行)
2. 理解输入输出 (黑盒)
3. 追踪主流程 (主干)
4. 深入细节 (分支)
5. 尝试修改 (实践)
6. 总结记录 (输出)
```

## 项目驱动学习

### 选择项目的标准

```
✓ 解决自己的真实需求
✓ 规模适中 (2-4周可完成)
✓ 涉及想学的技术栈
✓ 有明确的完成标准
```

### 项目进度节奏

```
Day 1:    环境搭建 + 最小原型
Day 2-3:  核心功能实现
Day 4-5:  边界情况处理
Day 6:    测试 + 文档
Day 7:    复盘 + 发布
```

## 知识管理

### 笔记结构

```markdown
# [主题名称]

## 一句话总结
> ...

## 核心概念
- 概念1: 解释
- 概念2: 解释

## 代码示例
```code
...
```

## 常见问题
Q: ...
A: ...

## 参考资料
- [链接1]
- [链接2]
```

### 知识连接

```
遇到新概念 → 与已知概念建立联系 → 形成知识网络
```

例如:
- 量化交易的"止损" ↔ 编程的"异常处理"
- 智能合约的"重入" ↔ 多线程的"竞态条件"

## 学习资源优先级

```
1. 官方文档 (最权威)
2. 源代码 (最真实)
3. 高质量博客/教程
4. 视频课程 (辅助)
5. 书籍 (系统性学习)
```

---

## 避免的陷阱

| 陷阱 | 解决方案 |
|------|----------|
| 教程地狱 | 设定明确目标，学够用就动手 |
| 完美主义 | 先完成，再完美 |
| 孤立学习 | 加入社区，分享输出 |
| 只输入不输出 | 写博客/做项目/教别人 |
| 追新技术 | 先精通基础，再扩展 |
